# gh-10-vocabulary-from-a-central-url.1 Fetcher, cache and status types for a remote vocabulary

## Description
Builds the self-contained pieces of the remote vocabulary, with no wiring into settings, engines or UI yet: the source enum, address validation, the HTTP fetcher, the on-disk cache, the status type with its user-facing messages, and a pure content-validation function shared with the local file. This is the early proof point (spec § Early proof point): it pins the HTTP behaviour (304 surfaces, Bearer header, refused redirect, byte cap, HTML rejection) and that an atomic cache replace yields a new file revision, before anything depends on it.

**Size:** M
**Files:** `app/MeetingTranscriber/Sources/RemoteVocabulary.swift` (new), `app/MeetingTranscriber/Sources/RemoteVocabularyFetcher.swift` (new), `app/MeetingTranscriber/Sources/RemoteVocabularyCache.swift` (new), `app/MeetingTranscriber/Sources/AppSettings+Vocabulary.swift`, `app/MeetingTranscriber/Sources/AppPaths.swift`, tests below
**Touches:** [app/MeetingTranscriber/Sources/RemoteVocabulary.swift, app/MeetingTranscriber/Sources/RemoteVocabularyFetcher.swift, app/MeetingTranscriber/Sources/RemoteVocabularyCache.swift, app/MeetingTranscriber/Sources/AppSettings+Vocabulary.swift, app/MeetingTranscriber/Sources/AppPaths.swift, app/MeetingTranscriber/Tests/RemoteVocabulary*.swift, app/MeetingTranscriber/Tests/CustomVocabularyValidationTests.swift]

### Approach
Write the tests first for each contract below (clear contracts, spec R2/R3/R5), see them fail for the stated reason, then implement.

1. **Content validation (refactor, behaviour-preserving).** Extract the body of `AppSettings.refreshCustomVocabularyValidation()` (`AppSettings+Vocabulary.swift:70-87`) into a pure static function on `CustomVocabularyValidation` that judges a byte count plus lazily read UTF-8 contents, in the same order (size → decode → terms → empty → count → term length), and a `validate(data: Data)` convenience for downloads (non-UTF-8 → `.unavailable`). `refreshCustomVocabularyValidation()` calls it; its results must not change. Equivalence harness: the existing `AppSettingsTests` / `TranscriptionSettingsVocabularyTests` validation cases stay green unmodified, plus new `CustomVocabularyValidationTests` covering each case on `Data` (empty, whitespace-only, 257 terms, a 513-byte term, 256 KB + 1 byte, invalid UTF-8, a valid list with duplicates counted once).
2. **`RemoteVocabulary.swift`**: `enum VocabularySource: String, CaseIterable { case file, url }` with labels "Local file" / "URL"; address validation (trim whitespace; empty, not `https`, or no host are distinct problems; returns the `URL`); the validators value (ETag, Last-Modified); the sidecar metadata (`url`, `etag`, `lastModified`, `updatedAt`, `checkedAt`; Codable, ISO-8601 dates); the failure enum (offline, HTTP status code, redirect refused, not a text file, too large, invalid content carrying a `CustomVocabularyValidation`, could not save, unexpected 304, cancelled); the fetch result (modified with body and response validators / not modified / failed); and `RemoteVocabularyStatus` (inactive, address problem, not downloaded, checking, current with term count + updatedAt + checkedAt, failed with the failure and the last good copy if any) with a pure `message(formatDate:)` producing the sentences in spec R4/R5/R7 (for example "No connection to the server · using the copy from <date> (<n> terms)", "Access denied (HTTP 401) – check the access token", "The address redirects to another server; the token is not sent there", "The address returned a web page, not a text file", "Not downloaded yet – no vocabulary in use"). Reuse `CustomVocabularyValidation.message` wording for invalid content.
3. **`RemoteVocabularyFetcher.swift`**: protocol `RemoteVocabularyFetching: Sendable` with one `fetch(url:token:validators:) async -> RemoteVocabularyFetchResult` (pattern: `UpdateProviding`, `UpdateChecker.swift:20-23`); a URLSession implementation whose session is injectable (tests) and by default its own ephemeral configuration with `urlCache = nil`, `requestCachePolicy = .reloadIgnoringLocalCacheData`, request (idle) timeout 30 s. Bound the whole fetch with a total deadline (60 s, injectable for tests) by racing it in a `withThrowingTaskGroup` against a sleep, as `OpenAIProtocolGenerator` does (`OpenAIProtocolGenerator.swift:125-150`); on the deadline cancel the transfer and return a timed-out failure (add the case to the failure enum, message "The server did not answer in time"). GET only. Sends `If-None-Match` / `If-Modified-Since` only when validators are passed; `Authorization: Bearer <token>` only when the trimmed token is non-empty (header pattern: `OpenAIProtocolGenerator.swift:122`). Redirect policy as a pure static function (`allows(from:to:tokenPresent:)`): never to a non-https URL; with a token, never to a different host (case-insensitive); applied through a task delegate's `willPerformHTTPRedirection` (completing with nil makes the 3xx the result → `redirectRefused`). Status mapping: 200 → check `Content-Type` (a `text/html` media type → not a text file), cap the body at `WhisperVocabularyPrompt.maximumFileBytes + 1` bytes (reject early on a larger `expectedContentLength`, and stop reading once over the cap, e.g. `bytes(for:delegate:)`), return the body with the response's `ETag` / `Last-Modified`; 304 → not modified if validators were sent, else unexpected 304; any other status → HTTP status; `URLError.cancelled` → cancelled; any other transport error → offline.
4. **`RemoteVocabularyCache.swift`**: a value type over a directory and a bundle identifier. A static, pure `textFile(in:bundleID:address:)` returns `remote-vocabulary-<bundle id>-<first 16 hex digits of SHA-256 (CryptoKit) of the trimmed address>.txt`; the sidecar sits beside it (same stem, `.json`). The sidecar metadata carries the SHA-256 of the text it describes. `load(for address:)`: no text, or text that fails step 1's validation → delete the pair, nil; text valid → return it as this address's copy, with the sidecar's validators and dates only when the sidecar decodes, names that address and its hash equals the text's hash; otherwise delete the sidecar and return the text with no validators and `updatedAt` = the text file's modification date (spec § Architecture "Cache"). `store(_:metadata:)` is the three-step commit: create the directory, write the text to a temporary file in the same directory, write the sidecar atomically, rename the temporary file over the text file (`FileManager.replaceItemAt` is not used: its behaviour on throw is undocumented, see the echo-cancellation note in CLAUDE.md; use a plain rename and remove the temporary file on any failure). It throws on any failure; a throw before the rename leaves the previous pair untouched. Put a DEBUG-only fault seam on the three steps (pattern: `ParakeetEngine.installVocabularyPreparationForTesting`, `ParakeetEngine.swift:235-241`) so tests can fail each one. `updateMetadata(_:)` rewrites only the sidecar. `discard(for:)` removes both, tolerating absence. `discardAll(except address:)` removes this bundle's copies (prefix `remote-vocabulary-<bundle id>-`) for every other address, logging and skipping any file it cannot delete; other bundles' files are never touched. Term count is derived from the text with the validation in step 1, never stored.
5. **`AppPaths.remoteVocabularyCacheDirectory`**: `dataDir/vocabulary`. The bundle identifier in the file name follows `AppPaths.livenessMarker` (`AppPaths.swift:51-55`): dev and release builds share `dataDir`.

### Key context
- Write a dedicated stub (`RemoteVocabularyURLProtocolStub`) that records every request it sees and can answer 200/304/4xx, a transport error, an HTML 200, an oversized body and a redirect; reset its static state in `tearDown`. Modelling a *refused* redirect through `URLProtocol` is unreliable: if the stub cannot show it, test the redirect policy as the pure function (all four from/to/token cases) and keep a stub test for an accepted same-host redirect.
- Pin that a 304 reaches the fetcher's result as "not modified" through a real `URLSession` with the production configuration plus the stub, not through a fake.
- Total deadline test: a stub mode that delivers a response and a first chunk and never finishes (like `MockURLProtocol.hangHandler`), with a deadline of a fraction of a second; assert the timed-out failure arrives promptly.
- Commit fault tests: fail the temporary write, the sidecar write and the rename in turn; each time the previous text stays byte-identical and `store` throws; after a rename failure, `load(for:)` returns the previous text with no validators, so a following 304 cannot pin it.
- Cache test: store two different same-length texts in a row and assert `WhisperVocabularyPrompt.fileRevision(at:)` differs; that is what makes both engines re-read the copy (spec § Architecture).
- Tests use a fresh temporary directory per test for the cache, never `AppPaths.remoteVocabularyCacheDirectory`.
- Pin the file name: two addresses differing only by surrounding whitespace map to the same file, two different addresses to different files, two bundle identifiers to different files; `discardAll(except:)` leaves the kept address's pair and another bundle's files in place.
- No `#if APPSTORE` is needed; the App Store variant has `com.apple.security.network.client`.
- Do not edit `CLAUDE.md` or `AGENTS.md` (fork rule); put the rationale (304 vs URL cache, text-then-sidecar order, redirect policy) in the new types' doc comments.

## Acceptance
- [ ] `CustomVocabularyValidation` has a pure validation for bytes/contents used by both the local file and downloads; existing local-file validation results are unchanged (existing tests green, unmodified).
- [ ] Address validation rejects empty, non-https and host-less input with distinct problems and trims whitespace.
- [ ] Fetcher tests through a real `URLSession` + dedicated stub prove: validators sent only when given; a 304 surfaces as not modified; `Authorization: Bearer <trimmed token>` only with a non-empty token and never a `PRIVATE-TOKEN` header; `text/html` rejected; a body over 256 KB rejected without holding more than the cap + 1 byte; 401/404/500 map to their status; a transport error maps to offline; a response that never finishes ends as timed out at the (injected) total deadline.
- [ ] Redirect policy: refuses any non-https target, refuses a cross-host target with a token, allows a same-host https target; the fetcher applies it.
- [ ] Cache: one file pair per (bundle identifier, trimmed address); the commit is temporary text → sidecar (with the text's SHA-256) → rename, and an injected failure at each step leaves the previous text byte-identical and throws; `load(for:)` deletes the pair for missing or invalid text, and returns valid text without validators (sidecar deleted) when the sidecar is missing, corrupt, foreign or its hash does not match; two successive stores of same-length texts give different `fileRevision`s; `discardAll(except:)` removes only this bundle's other addresses.
- [ ] `RemoteVocabularyStatus.message(formatDate:)` has a test per case with a fixed date formatter.
- [ ] `AppPaths.remoteVocabularyCacheDirectory` exists as a constant under `dataDir`.
- [ ] Focused tests, lint and `swift build -c release` pass.
