## Description
Regenerate Protocol becomes a sheet of the All Recordings window: a row opens it with that row's meeting filled in and no "Choose File…" step, the toolbar's "Regenerate from File…" opens it empty with "Choose File…". The separate window, its scene, its menu item and task .4's interim closure go away (A3, A4). The form, the Generate rules, the Trash step and the error text are today's.

### Approach
- **The view's seed.** `RegenerateProtocolView` (`RegenerateProtocolView.swift:41-51`) replaces its `latestTarget: () -> ProtocolRegenerationTarget?` input with `initialTarget: ProtocolRegenerationTarget?` and `allowsChooseFile: Bool`; the `onAppear` reset (`:101-105`) seeds the draft from `initialTarget` (nil leaves the meeting block at `noMeeting`, `:39`) and never from `latestTarget()`, which would regenerate the wrong meeting from a row. "Choose File…" (`A11yID.regenerateChooseFileButton`) renders only when `allowsChooseFile`. The dismiss button reads "Cancel" (was "Close", `:185`; keeps `.cancelAction`; new `A11yID.regenerateCancelButton`). Generate's rule (`:83-86`: no target, running, destination off, record-only) and `A11yID.regenerateGenerateButton` stay; the headline, `ProtocolOptionsForm`, `trashNote` and `unknownDateNote` stay.
- **The presenter.** `RegenerateSheetState` (`@Observable`, a reference type so tests assert on it) owned by the App and injected into `TranscriptionsView`: `isPresented`, `initialTarget`, `allowsChooseFile`, and `present(entry: TranscriptionEntry?)`. For a row it builds a row-aware target through a new `ProtocolRegenerator.target(for entry: TranscriptionEntry) throws` beside `target(for: URL)` (`ProtocolRegeneration.swift:309`): the files come from `ProtocolRegenerationTarget.readFiles` on the row's folder and basename, and the identity comes from the row, `title` from `entry.title`, `jobID` from `entry.id`, `meetingStartTime` from a new `TranscriptionEntry.meetingStartTime` field (set from `job.meetingStartTime` and `record.meetingStartTime` in both inits, `TranscriptionList.swift:43,63`; nil for an import, whose `date` is the enqueue time and must never be shown as a meeting time, the repo's rule for protocol metadata). The history is not consulted for a row: a failed job stays listed after its record left the 1000-entry history (`TranscriptionList.swift:86-95`), and `resolve(file:records:read:)` (`:149-169`) would then fall back to a filename-derived title and nil date and job id, losing what the row already shows. A thrown `ProtocolRegenerationError.noTranscript` (the file went away between menu build and click) sets `TranscriptionsFileNotice.fileMissing` and leaves the sheet closed, the same path as "The file was moved or deleted.". For nil it opens with `initialTarget == nil` and `allowsChooseFile == true`. Every `present` calls `protocolRegenerator.clearResult()` first, which the old scene did on appear (`MeetingTranscriberApp.swift:385`), so a previous run's success never shows on a new row. `TranscriptionsView` attaches `.sheet(isPresented:)` on its root and builds the view with the presenter's values plus today's `templateChoices`, `optionsUse`, `chooseFile`, `resolveFile`, `onGenerate` closures (`:373-384`); `onClose` sets `isPresented = false`.
- **While a run is in flight,** closing the sheet changes nothing: `regenerate` (`ProtocolRegeneration.swift:320-341`) runs on the controller and reports success or failure as a notification; the rows' Regenerate items stay enabled and a reopened sheet shows `.running` with Generate disabled, today's rule. The failure text shown in the sheet stays the `phase.failed(reason)` string the view shows today; add no new route for provider error text (memory entry `bug/security/provider-error-text-shown-in-a-2026-10-13`).
- **Wiring.** `AllRecordingsActions.regenerate` becomes `sheetState.present(entry:)`, replacing task .4's interim `bringWindowToFront`. Remove `regenerateProtocolWindow` (`MeetingTranscriberApp.swift:371-388`) and its entry in the scene list (`:143-144`), `RegenerateProtocolView.windowID` (`:36`) and the `closeWindow(id:)` call, the menu item (`MenuBarView` Recordings section, originally `:348-353`), `MenuActions.regenerateProtocol`, `A11yID.regenerateProtocolMenuItem` (`:159`) and `MenuBarViewTests.swift:428-440`. Update the header comments that describe the window (`RegenerateProtocolView.swift:6,31`, `AppState.swift:92`).
- **Tests.** `RegenerateProtocolViewTests` (`:5` describes the window): seeded from a row the meeting block shows the title, the date line and the protocol file name and has no "Choose File…"; opened empty it shows "Choose File…" and `noMeeting` with Generate disabled; the Cancel wiring test by `A11yID.regenerateCancelButton`; the existing Generate, destination-off and record-only tests (`:51`, `:72`, `:98`) kept. `RegenerateSheetStateTests`: `present(entry:)` with a resolvable row opens with that target and `allowsChooseFile == false`; a failed live job whose history record was evicted keeps its title, meeting start and job id in the target; an import row yields a nil meeting start (the `unknownDateNote` case); with a row whose files are gone it sets the notice and stays closed; `present(nil)` opens empty; `clearResult` is called on each `present`. `TranscriptionListTests`: `meetingStartTime` is set from a job's and a record's meeting start and nil for an import. `TranscriptionsViewTests`: the row's Regenerate item and the toolbar button reach `present(entry:)` with the row and with nil. `MenuBarViewTests`: "Regenerate Protocol…" is absent (R3).
