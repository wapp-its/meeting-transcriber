# gh-7-protocol-via-codex-cli-and-a-custom.2 Codex CLI preset and custom command providers

## Description
Add the Codex CLI preset and the custom command as one `CommandProtocolGenerator` on the runner from task .1, the two new providers and their settings, and the factory wiring, so a protocol is produced end to end once a provider is chosen (the Settings controls are task .3). The placeholder rules live in a pure `CommandTemplate` type so most of the contract is tested without starting a process.

### Approach

- `CommandTemplate` (pure, whole file `#if !APPSTORE`), signatures only:
  - `static func effectiveArguments(_ stored: [String]) -> [String]` — each entry trimmed of surrounding whitespace, empty entries dropped; the first is the program.
  - `enum Placeholder: String, CaseIterable { case model = "{model}", promptFile = "{prompt_file}", transcriptFile = "{transcript_file}", outputFile = "{output_file}" }`.
  - `static func uses(_ placeholder: Placeholder, in arguments: [String]) -> Bool` — looks at the arguments after the program only.
  - `static func substitute(_ arguments: [String], values: [Placeholder: String]) -> [String]` — program left untouched; one left-to-right scan per argument, so a substituted value is never scanned again (a model named `{prompt_file}` stays literal); an unknown `{name}` stays as typed.
  - Input mode: files when `{prompt_file}` or `{transcript_file}` is used, else stdin. Output mode: file when `{output_file}` is used, else stdout.
- `CLIProcessRunner.resolveProgram(_ program: String, environment: [String: String], home: String = NSHomeDirectory()) -> URL?` (added here to the runner from .1): an absolute path is used when it is an executable file; a leading `~/` is expanded against `home`; a bare name (no `/`) is searched in `searchPaths`, then in the `PATH` entries of `environment`; anything else returns nil. The Claude preset keeps `resolveClaudePath` and its `/usr/bin/env` fallback.
- `struct CommandProtocolGenerator: ProtocolGenerating` (whole file `#if !APPSTORE`) holding a tool label, the argument template (program first), the model, the language, `timeout` (default `CLIProcessRunner.defaultTimeout` from task .1), `maxOutputBytes` (default 32 MiB, injectable for the cap test), `promptURL` (default `AppPaths.customPromptFile`, injectable so tests never read the developer's custom prompt) and an optional failure-reason function over the runner's `Output`. Static factories: `codex(language:program:)` with `program` defaulting to `"codex"` (tests pass a fake script path) and `custom(arguments:model:language:)`.
- Codex template, exact: `[program, "exec", "--json", "--ephemeral", "--skip-git-repo-check", "--sandbox", "read-only", "--output-last-message", "{output_file}", "-"]`, tool label "Codex CLI". Custom: the effective stored arguments, tool label "Custom command".
- `generate` flow, split into helpers to stay under the 60-line body limit: validate (no program → `.commandNotConfigured("No custom command is set")`; `{model}` used with a blank model → `.commandNotConfigured("The custom command uses {model}, but no model is set")`) → prompt from a new shared helper `ProtocolGenerator.fullPrompt(transcript:diarized:language:meetingStartTime:promptURL:)` (= `buildSystemPrompt(...) + transcript`, the composition at `ClaudeCLIProtocolGenerator.swift:45`, which switches to the helper too) → environment `CLIProcessRunner.environment(base: ProcessInfo.processInfo.environment)` → `resolveProgram` or `.commandNotFound(tool:program:)` with the program's last path component, before anything starts → `makeRunDirectory` with `defer` removal → write `prompt.txt` (the full prompt bytes) and `transcript.txt` only when their placeholder is used, owner-only via `FileManager.restrictToOwner` (`FileManager+OwnerOnly.swift:22`) → output path `protocol.md` in the run folder → substitute → run (stdin = the prompt bytes in stdin mode, nil otherwise) → map runner failures (`.couldNotStart` → `.commandNotFound`, `.timedOut` → `.commandTimedOut(tool:)`, `.stdoutTooLarge` → `.commandOutputTooLarge(tool:)`) → non-zero exit → `.commandFailed(tool:exitCode:reason:)` with the reason from the failure-reason function (nil for custom) → zero exit → read the output file safely or take stdout: open the fixed output path with `open(path, O_RDONLY | O_NOFOLLOW | O_NONBLOCK)`, `fstat` the descriptor and require a regular file, then read at most `maxOutputBytes + 1` bytes from that descriptor (a missing file, a symlink, a FIFO or any non-regular file → `.commandProducedNoProtocol`; more than the cap → `.commandOutputTooLarge`); the output file's mode is the program's business (the folder is 0700), so the app does not chmod it; decode UTF-8 lossily (`String(decoding:as:)`), trim, empty → `.commandProducedNoProtocol(tool:)`.
- Codex failure reason, `static func codexFailureReason(_ output: CLIProcessRunner.Output) -> String?`: the message of the last stdout JSON line `{"type":"turn.failed","error":{"message":…}}`, else of the last `{"type":"error","message":…}`; else, when stderr contains `unexpected argument`, the fixed hint "This Codex CLI does not know an option the app needs (such as --ephemeral). Update Codex."; capped at 300 characters. These shapes are Codex's documented `--json` events and were not checked against a live run; an unknown shape yields nil, never a crash.
- `ProtocolError` (`ProtocolGenerator.swift:264-296`), new cases inside the `#if !APPSTORE` block: `commandNotFound(tool: String, program: String)`, `commandFailed(tool: String, exitCode: Int32, reason: String?)`, `commandTimedOut(tool: String)`, `commandProducedNoProtocol(tool: String)`, `commandNotConfigured(String)` (only app-written text). Descriptions name the tool and never contain stdout, stderr, argument values or the model.
- Logging (`Logger` category "CommandProtocolGenerator", pattern `ClaudeCLIProtocolGenerator.swift:6`): `.public` only for the tool label, program file name, argument count, stdin byte count, input and output mode, exit code and elapsed time; stdout and stderr (at most 2 KiB each) only at `.private`.
- Settings (`AppSettings.swift`): add `codexCLI` and `customCommand` to `ProtocolProvider` inside its `#if !APPSTORE` (`:98-116`), order claudeCLI, codexCLI, customCommand, openAICompatible, none, labels "Codex CLI" and "Custom Command"; add `customCommandArguments: [String]` and `customCommandModel: String` (`#if !APPSTORE`, `didSet` persisting under keys of the same name, loaded in `init` beside `claudeBin` at `:704-711`, defaults `[]` and `""`); add computed `customCommandText: String` (get: entries joined with `"\n"`; set: `components(separatedBy: "\n")`), a lossless round trip that the editor in task .3 binds to.
- `OutputSettingsView.providerConfigView` (`OutputSettingsView.swift:114-150`) is an exhaustive `switch` without `default`: add the two cases inside its `#if !APPSTORE` with one interim caption each (for example "Configured in the next step."), so this task builds and its tests run; task .3 replaces them with the real controls.
- Factory `PipelineController.makeProtocolGenerator` (`PipelineController.swift:348-371`): `.codexCLI` → `.codex(language:)`, `.customCommand` → `.custom(arguments: settings.customCommandArguments, model: settings.customCommandModel, language: settings.protocolLanguage)`.
- `RPCStateSnapshot.swift:397`: the doc comment lists the two new raw values; no new fields (a command line can carry a key).

### Key context

- Tests first. `CommandTemplateTests` (pure): trimming and blank-line dropping; `uses` ignores the program; substitution inside an argument (`--prompt-file={prompt_file}`), repeated placeholders, unknown `{name}` kept, a value containing a placeholder not re-expanded; input/output mode; validation errors. `CommandProtocolGeneratorTests` (fake `#!/bin/sh` scripts, pinned prompt file):
  - stdin mode returns the program's stdout, and the stdin bytes equal the pinned prompt followed by the transcript; with `{prompt_file}`, that file's bytes equal those stdin bytes and the program's stdin is empty; `{transcript_file}` holds the transcript alone; input files are `0600` and the folder `0700`; with `{output_file}` the file's content is the protocol and stdout is ignored; a missing output file → `.commandProducedNoProtocol`; a symlink at the output path pointing at a file with other text → `.commandProducedNoProtocol` and that text never returned; a FIFO made at the output path (`mkfifo`) → `.commandProducedNoProtocol` within a second, no hang; an output file over an injected 1 KiB cap → `.commandOutputTooLarge`.
  - an argument `{transcript_file};touch pwned`, a model `$(touch pwned2)` and an argument with quotes each arrive as one unchanged argument and no file is created.
  - program not found (unknown bare name, relative `bin/tool`) throws `.commandNotFound` and nothing starts; `~/` expands against an injected home.
  - a fake that prints the transcript to stderr and exits 2 throws `.commandFailed(exitCode: 2, reason: nil)` whose `errorDescription` contains neither the transcript nor the stderr text (A5's test).
  - Codex: the template pinned exactly; a fake `codex` that reads stdin and writes the path after `--output-last-message` yields that protocol; one printing a `turn.failed` line and exiting 1 yields that message as the reason; one printing `error: unexpected argument '--ephemeral' found` to stderr and exiting 2 yields the update hint.
