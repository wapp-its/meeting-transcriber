# gh-97-delete-recordings-by-hand-and-after-a.1 Meeting file record: the store and a recorded meeting's files

## Description
The early proof point: the meeting file record (spec "Architecture & Data Models": meeting file record, paths and ownership, recording date, meeting outcome, one writer) and its store, the shared presence probe, plus the hooks that make it follow a **recorded** meeting from the hand-over to its finish. Every later task reads this record, so it comes first and is proven end to end through the real queue. Imports, recovery, retry, cancel, naming-file removals, Regenerate Protocol and the segments permission are task .2.

### Approach
- **Shape** (signatures only; the worker names the rest):
  - `struct MeetingFileRecord: Codable, Equatable, Sendable`: `jobID: UUID`, `origin: Origin` (`.recorded`, `.imported`), `recordingDate: Date?`, `files: [MeetingFile]`, `keep: Bool`, `outcome: Outcome` (`.inProgress`, `.finished(protocolExpected: Bool)`, `.failed`, `.leftUnfinished`), `audioDeletion: AudioDeletion?` (`kind`: manual or automatic, `at: Date`), `incomplete: DeletionFailure?` (reason text, the paths not removed, the kind to retry), `pending: PendingDeletion?` (task .3 fills it), `excludedFromAutomaticDeletion: Bool` (task .2 sets it for a recording from before this feature). Decode every field after `jobID`, `origin` and `files` as optional with a default, as `TerminalJobRecord` does, so a later field never makes a whole record unreadable.
  - `struct MeetingFile: Codable, Equatable, Sendable`: `role: Role` (`.mix`, `.appTrack`, `.micTrack`, `.mix16k`, `.app16k`, `.mic16k`, `.segments`, `.naming`, `.transcript`, `.protocol`, `.previousProtocol`), `path: String` (stored after `resolvingSymlinksInPath()`), `identity: FileIdentity?` (device and inode from `lstat`, taken when the file is recorded), `owned: Bool`, `state: State` (`.present`, `.deleting`, `.gone`). `Role.isAudio` is true for the three tracks and the three 16 kHz copies.
  - `@MainActor @Observable final class MeetingFileStore`: `init(path: URL)`, `private(set) var records`, `func create(_:) -> Bool`, `func update(jobID:, _ change: (inout MeetingFileRecord) -> Void) -> Bool`, `func remove(jobID:) -> Bool`, `func reload()`, `func record(for:) -> MeetingFileRecord?`, `var since: Date`. Each write returns whether it was saved, because task .3 starts a deletion only after its pending mark is on disk. All records live in one JSON file, `meeting_files.json`, beside `terminal_jobs.json`, as an object holding `since` (when the file was first created) and `records`; `since` is how task .2 recognises a recording from before this feature.
- **Writes** (spec "One writer"): each `create`/`update`/`remove` takes an exclusive `flock` on `meeting_files.json.lock`, re-reads the file, applies the change to the disk copy of that one record, writes atomically and owner-only exactly as `TerminalJobStore.save()` does (`TerminalJobStore.swift:76-95`), then releases the lock. Re-reading alone is not enough: two processes (the development and the release build share the data folder) could both read before either writes. Take the lock with `LOCK_NB` in a short retry loop bounded at about two seconds, so a stuck holder fails the write (logged, returns false) instead of hanging the main actor; the kernel drops a lock when its process dies. Never hold the lock outside one read-change-write. A failed write is logged and never thrown into the pipeline. A file that does not decode is moved aside once (`meeting_files.json.corrupt`) instead of being overwritten by an empty list.
- **Presence** (spec "Reachable versus gone"): `enum MeetingFilePresence { case present, gone, unreachable }` with `static func of(_ path: String) -> Self` built on `lstat` and its `errno`: gone only on `ENOENT` for the file while its parent folder can be opened for reading; a missing parent, `EACCES`, `EPERM`, `EIO` or any other error is unreachable. Task .2, task .3, the row cache (task .5) and the check (task .6) all use this one probe. Also `FileIdentity.of(_ path:) -> FileIdentity?` from the same `lstat`.
- **Wiring**: build the store in `PipelineController.init` next to `TerminalJobStore` (`PipelineController.swift:109-112`), injectable the same way, and hand it to the queue where `terminalJobStore` is passed (`makeQueue`, around `:280-317`).
- **Creation** in `PipelineQueue.enqueue` (`PipelineQueue.swift:526`): add an `origin:` parameter defaulting to `.imported`, the safe side (a caller that forgets makes a meeting the app never deletes, and the 169 existing test calls compile unchanged); pass `.recorded` from the watch loop (`WatchLoop.swift:548`) and `.imported` from the import call sites (`PipelineController.swift:462`, `:477`); task .2 tests the import side and adds orphan recovery, which appends jobs without `enqueue`. Owned is `origin == .recorded` for the three track paths the job carries. `recordingDate` is `meetingStartTime ?? enqueuedAt` for a recording, nil for an import, written once here and never changed.
- **Following the files** (recording path): `recordRelocatedAudio` (`PipelineQueue.swift:834`) replaces the track paths with the ones reported; the transcript draft and final transcript (`PipelineQueue+Stages.swift:140-146`, `:856-860`); the 16 kHz copies after their `try?` moves (`:879-891`), listing only a copy that exists after the move; the segments file (`:895-897`); the protocol (`:981`). Each listed file gets its `identity` when it is listed or its path changes. Route every app write of a listed file through one record helper (for example `noteWritten(jobID:role:path:)`) that stores the path and the new identity, because an atomic write replaces the file and with it its inode: a writer that skips the helper makes task .3 refuse the app's own file as replaced. That failure is safe (the file is reported, never removed), but it leaves the meeting stuck as incomplete, so task .2 names every later writer and tests each.
- **Outcome**: in `generateProtocol` (`PipelineQueue+Stages.swift:940`), record `protocolExpected = false` on the early return when no generator is configured (`:943-945`) and `true` past it; at the terminal transition in `applyJobState` (`PipelineQueue.swift:741-746`) set `.finished(protocolExpected:)` for `.done` and `.failed` for `.error`. A protocol that fails to generate or save still ends `.done` (`:983-987`), which is why `protocolExpected` exists.
- **Tests, written first**: `MeetingFileStoreTests` against a temp file (round trip; `since` is written once and kept; two store instances on one file each writing their own record keep both; store A reads, store B sets Keep, store A then changes its outcome, and Keep survives; a write waits while another file handle holds the lock and lands after it is released; a write fails and returns false when the lock is held past the bound; a corrupt file is moved aside; a write into an unwritable folder returns false and logs); `MeetingFilePresenceTests` (present file; a removed file in a readable folder is gone; a missing parent folder is unreachable; a parent without search permission makes its existing child unreachable, not gone); `PipelineQueueMeetingFilesTests` drives one recorded job through the queue with the mocks of `PipelineQueueHistoryRecordTests` (`Tests/PipelineQueueHistoryRecordTests.swift:20-31`) and asserts the record lists the relocated tracks, transcript and protocol as owned and present, outcome `.finished(protocolExpected: true)`, and that a fresh store on the same file reads the same record; with `protocolGeneratorFactory: { nil }` the outcome is `.finished(protocolExpected: false)` with no protocol listed; with a generator that throws, `.finished(protocolExpected: true)` with no protocol listed.

### Key context
- The queue is `@MainActor`; keep every record change on it, never from a detached task.
- `persistAudioToOutput` reports the source path when a move failed (`PipelineQueue+Stages.swift:1075-1125`): record what it reports, never the intended destination.
- `meeting_files.json` lists output paths and meeting slugs, the same sensitivity as `terminal_jobs.json`: owner-only, never logged with `.public` privacy.
## Acceptance
- [ ] A recording run through the queue leaves one record in `meeting_files.json` listing its relocated tracks, any 16 kHz copies still present, the segments file, the transcript and the protocol, each owned and present, with the recording start as its recording date and outcome finished with protocol expected; a new store on the same file reads the same record (R1).
- [ ] With no protocol generator the outcome is finished without protocol expected; with a generator that fails the outcome is finished with protocol expected and no protocol is listed (R1, spec "Meeting outcome").
- [ ] A failed run ends with outcome failed; a run without a recording start records the time it entered processing as its recording date (R1, A6).
- [ ] Every write holds an exclusive lock across re-reading, changing and writing; a Keep set by one store between another store's read and write survives; a write that cannot get the lock in time fails and reports it; two store instances writing different records to one file keep both; a file that does not decode is moved aside, not overwritten; a failed write is logged and does not fail the job (R1).
- [ ] The presence probe calls a file gone only when the file system confirms it is absent from a readable folder; a missing folder or a permission or access error is unreachable (R1, spec "Reachable versus gone").
- [ ] `MeetingFileStoreTests`, `MeetingFilePresenceTests` and `PipelineQueueMeetingFilesTests` were written before the implementation and pass; the spec's quick command stays green.
