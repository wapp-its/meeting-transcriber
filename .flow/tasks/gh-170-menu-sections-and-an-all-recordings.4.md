- **Availability store.** SwiftUI builds `Menu` and `.contextMenu` content before presentation (measured by the plan reviewer with a local probe), so `filesOnDisk` would otherwise run on every redraw of every row, and `readFiles` reads both files. `RowAvailability` (`@Observable`, injected like `TranscriptionsFileNotice`) caches `FilesOnDisk` per entry id: a row resolves on its first render (`List` renders only the visible rows), and the store drops every cached value when `entries` change, when the window appears or becomes key (`NSWindow.didBecomeKeyNotification`), and after a row action (open, reveal, retry, remove, regenerate) returns. A transcript restored in Finder is therefore seen the next time the window is activated; the store's doc comment states that bound. Each item carries an index-addressed id (`A11yID.recordingMenuOpenProtocol(index)`, `...OpenTranscript`, `...ShowInFinder`, `...Regenerate`, `...Retry`, `...Remove`, `...Dismiss`). A false result from open/reveal sets `TranscriptionsFileNotice.fileMissing` as today (`:85`); Show in Finder reveals the protocol, else the transcript.
- **Menu.** Remove "Open Protocols Folder" from the Recordings section task .2 built in `MenuBarView` and `MenuActions.openProtocolsFolder`; move its tests (`MenuBarViewTests.swift:202`, `:374`) to `TranscriptionsViewTests` as the toolbar button's wiring test.
- **Docs.** `.github/README.md:27` and `docs/automation-api.md:169` name the Transcriptions window; say "All Recordings window" (and keep Cmd-T). `CLAUDE.md` is not edited in this fork.
