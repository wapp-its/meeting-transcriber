### Approach
- **Title and id.** The scene `Window("Transcriptions", id: TranscriptionsView.windowID)` (`MeetingTranscriberApp.swift:353-368`) gets the title "All Recordings"; the id `"transcriptions"` and the type names stay (nothing user-visible depends on them, `bringWindowToFront` at `:184` and `TranscriptionsWindowPrivacyTests` read the id, and a rename is not asked for). Comments that say "Transcriptions window" in the touched files say "All Recordings window".
- **Actions value.** `AllRecordingsActions` (own file, the shape of `MenuActions`): `openProtocol(URL) -> Bool` and `openTranscript(URL) -> Bool` (both through `TranscriptionFileOpener`, as `openTranscriptionFile` at `:523`), `reveal(URL) -> Bool` (`:532`), `regenerate(TranscriptionEntry?)`, `retry(UUID)`, `remove(UUID)` (`PipelineController.removeFailedJob`, which already handles a history-only record), `dismiss(UUID)` (`pipelineQueue.removeJob`, as the menu's Dismiss at `:187`), `cancel(UUID)` (`pipelineQueue.cancelJob`), `nameSpeakers(UUID)` (A5: set `appState.selectedNamingJobID` to the row's job, then `bringWindowToFront(id: "speaker-naming")`), `openProtocolsFolder()` (the App's `openProtocolsFolder`, `:506-512`, moved as is: creates the folder, opens it, no message), `canRetry(UUID) -> Bool`, and `filesOnDisk(TranscriptionEntry) -> RecordingRowActions.FilesOnDisk`: `protocolExists` and `transcriptExists` via `FileManager.fileExists`, and `transcriptSource` from the regenerator's own reading code, `ProtocolRegenerationTarget.readFiles(folder:basename:read:)` (`ProtocolRegeneration.swift:137-142`) followed by `ProtocolRegenerationFiles.transcript` (`:99-108`: nil is `.none`, `fromProtocol` is `.protocolOnly`, else `.transcriptFile`), so the row's Regenerate item and the sheet never disagree about what is usable (a blank or non-UTF-8 `.txt` is `.none` unless the protocol holds the full transcript). Interim production `regenerate`: `bringWindowToFront(id: RegenerateProtocolView.windowID)` with a comment pointing at task .5. The window's production value is built next to the menu's in `MeetingTranscriberApp`.
- **Toolbar.** `.toolbar { }` on the window's root with the search `TextField` (keep `A11yID.transcriptionsSearchField`, the App-held `transcriptionsQuery` binding `:89-93` and `TranscriptionList.matching` untouched), "Open Protocols Folder" (`A11yID.recordingsOpenFolderButton`) and "Regenerate from File…" (`A11yID.recordingsRegenerateFromFileButton`, calls `regenerate(nil)`). No window shortcuts.
- **Rows** (`TranscriptionsView.swift:117-134`, `:173-195`): the text column stays; `fileActions`/`failureActions` are replaced by one main button from `RecordingRowActions.mainAction` (`A11yID.recordingMainButton(index)`, the label from the action: "Cancel", "Name Speakers", "Open Protocol", "Open Transcript", "Retry", "Remove"; absent when nil) and a "…" `Menu` (`A11yID.recordingMoreButton(index)`, disabled when the item list is empty) whose content is one `@ViewBuilder rowMenu(entry, index)` built from `RecordingRowActions.menuItems(state:onDisk:canRetry:)` with `onDisk` read from the `RowAvailability` store below; the same builder is attached as `.contextMenu` on the row's `HStack`, so the two menus are the same list by construction.
- **Availability store.** SwiftUI builds `Menu` and `.contextMenu` content before presentation (measured by the plan reviewer with a local probe), so `filesOnDisk` would otherwise run on every redraw of every row, and `readFiles` reads both files. `RowAvailability` (`@Observable`, injected like `TranscriptionsFileNotice`) caches `FilesOnDisk` per entry id: a row resolves on its first render (`List` renders only the visible rows), and the store drops every cached value when `entries` change, when the window appears or becomes key (`NSWindow.didBecomeKeyNotification`), and after a row action (open, reveal, retry, remove, regenerate) returns. A transcript restored in Finder is therefore seen the next time the window is activated; the store's doc comment states that bound. Each item carries an index-addressed id (`A11yID.recordingMenuOpenProtocol(index)`, `...OpenTranscript`, `...ShowInFinder`, `...Regenerate`, `...Retry`, `...Remove`, `...Dismiss`). A false result from open/reveal sets `TranscriptionsFileNotice.fileMissing` as today (`:85`); Show in Finder reveals the protocol, else the transcript.
- **Menu.** Remove "Open Protocols Folder" from the Recordings section task .2 built in `MenuBarView` and `MenuActions.openProtocolsFolder`; move its tests (`MenuBarViewTests.swift:202`, `:374`) to `TranscriptionsViewTests` as the toolbar button's wiring test.
- **Docs.** `.github/README.md:27` and `docs/automation-api.md:169` name the Transcriptions window; say "All Recordings window" (and keep Cmd-T). `CLAUDE.md` is not edited in this fork.
- **Tests** (`TranscriptionsViewTests`, by `A11yID`): one wiring test per control: the main button for each `MainAction` (the Name Speakers one asserts the row's job id reaches the closure, A5; the Cancel one asserts `cancel` ran), the "…" menu's items (find the `Menu`, then each item's button by id, tap, assert the closure argument), both toolbar buttons, and a test that the `Menu` holds exactly the items `RecordingRowActions.menuItems` returns for that row (parity with the context menu rests on the shared builder plus task .3's tests; no right-click simulation). `RowAvailabilityTests` (temp files): a removed transcript leaves Open Transcript out after the next refresh and a restored one brings it back after a refresh, a render between refreshes reads nothing (count the resolver calls), and the resolver yields `.none` for a blank or invalid-UTF-8 transcript without a protocol holding the full transcript and `.protocolOnly` with one. Keep the search and "The file was moved or deleted." tests; `TranscriptionsWindowPrivacyTests` stays green with the same id.
