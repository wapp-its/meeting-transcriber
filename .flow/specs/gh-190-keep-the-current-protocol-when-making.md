## Goal & Context

"Regenerate Protocol…" makes a finished meeting's protocol again with a chosen template and background info, and moves the previous protocol to the Trash, so a meeting has one protocol at a time. One meeting can need a report for each of several audiences, for example full minutes for the participants and a short summary for others. Today the user has to take the earlier protocol back out of the Trash and rename it by hand. With this spec the new protocol can be saved as an additional report next to the existing one.

## Architecture & Data Models

- **A meeting's files today:** the transcript `<basename>.txt` and the protocol `<basename>.md` in the output folder. That protocol stays the main protocol, with its role unchanged. A basename the app made has the form `<yyyyMMdd_HHmm>_<slug>_<short id>`, with no space or bracket in it. The mockup shortens these names for reading ("Budget review.md"); the sheet shows the real file names. [inferred]
- **Additional report:** a Markdown file in the same folder named `<basename> (<template name>).md`, so Finder sorts it next to the meeting. The template name is as the template picker shows it, except that the built-in template is called "Standard". It has the same document shape and the same owner-only file permissions as a regenerated protocol. [inferred]
- **Whose report a file is (one rule, used by the row's list, the sheet's count, the same-template check and "Regenerate from File…"):** a Markdown file with a transcript beside it under its own full name is a meeting of its own, never a report. Any other file whose name ends in `)` is split at each ` (`, and it belongs to the longest part before such a split that has a transcript beside it. `Budget (Q3) (Short).md` belongs to `Budget (Q3)` when `Budget (Q3).txt` exists, else to `Budget` when `Budget.txt` exists; `Budget (Alpha (Beta)).md` with only `Budget.txt` beside it is the report "Alpha (Beta)" of `Budget`. The text after the split, without its closing bracket, is the name the menu shows. A file with no such part is no report and resolves as today. A meeting a row already knows also keeps its reports when its transcript is gone: from the row's side, its reports are the files named `<basename> (…).md` that no longer meeting name claims. [inferred]
- **No list of reports:** nothing records them while the meeting lives, so a report deleted or renamed in Finder drops out, and a report whose template was deleted later stays listed. [inferred]
- **Moving a meeting to the Trash (gh-97):** when "Move Meeting to Trash…" is confirmed, and again on each "Retry Deletion", the app reads the folder of the meeting's transcript and protocol as its record lists them, and adds each report it finds to the record as an owned file with its identity on disk, in the same save that writes gh-97's pending deletion. From there gh-97's rules apply unchanged: the deletion starts only when that save succeeded, the same-file check right before each move, a result per file, the check after a restart, and the retry. A folder that cannot be read leaves the deletion incomplete, also when the record lists nothing else there, and the retry reads it again. When another record also lists the meeting's transcript or protocol, its reports count as shared too: they are blocked and stay, as gh-97 does for a shared path. [inferred]
- **Regenerate sheet (accepted mockup):** the template and background choice stay as they are. The meeting's lines gain the number of reports after the protocol's file name when there are any ("<file> · 1 additional report", "· 2 additional reports"). Between the background notice and the buttons comes the radio group "Save as:": [paraphrase]
  - "An additional report", with the small line "Saved as “<file>”. The current protocol stays as it is." When the chosen template already has a report, that line turns orange and reads "Replaces the existing “<file>”, which is moved to the Trash. The current protocol stays as it is."
  - "Replace the current protocol", with the small line "The current protocol is moved to the Trash and replaced."
- **All Recordings row (accepted mockup):** the "…" menu and the right-click menu show Open Protocol, Open Transcript and Show in Finder, then a separator, the non-interactive heading "Additional Reports" with one item per report in alphabetical order, another separator, and Regenerate Protocol…, followed by what gh-97 adds there. A row without reports shows neither the heading nor its separator. [paraphrase]

## Edge Cases & Constraints

- **No protocol yet** (protocol generation was off or failed): the result becomes the main protocol, as today, and the sheet offers no choice. [inferred]
- **Same template again:** saving an additional report for a template that already has one replaces that report the way Replace treats the main protocol, with the old file moved to the Trash; the main protocol is never touched. A user template named "Standard" shares its report file with the built-in template, so it counts as the same template here. [inferred]
- **The name is another meeting's protocol.** In a folder of hand-named files, the report's file name can be the protocol of a meeting of its own (`Budget (Q3).md` beside `Budget (Q3).txt`, for a template named "Q3"). The sheet then shows the orange line "“<file>” belongs to another meeting, so this template cannot be saved as an additional report here." and Generate is disabled while that choice is selected. A meeting the app named cannot meet this, since its names hold no space or bracket. [inferred]
- **Today's safety holds for both choices:** nothing is replaced when generation fails, when the meeting's files changed while the protocol was made, or when the write fails; the transcript is never changed. The report the run would write counts among those files, so a report that appeared, changed or vanished during the run stops it with today's message. A run that finishes after its meeting went to the Trash finds its transcript gone and writes nothing. [inferred]
- **A name too long for the volume** fails with the existing write-failed message, and nothing is replaced. [inferred]
- **A pipeline retry** of the job rewrites only the main protocol and leaves additional reports alone. [inferred]
- **Privacy:** template names are user text and appear in log lines only as private values. [inferred]

## Acceptance Criteria

- **R1:** For a meeting that already has a protocol, the Regenerate Protocol sheet offers the radio group "Save as:" of the accepted mockup, with the template and background choice as today. An additional report is written to `<basename> (<template name>).md` next to the meeting's files, and the main protocol and every other report stay unchanged. Errors: a meeting without a protocol gets its main protocol as today, with no choice shown; an additional report for the same template is replaced and the old one moved to the Trash, which the sheet says in its orange line before the user generates; a report name that is another meeting's protocol disables Generate with the orange line above; a failed generation, a failed write or meeting files that changed meanwhile leave every file as it was, with today's messages. [paraphrase]
- **R2:** A row in All Recordings lists each additional report of its meeting by its name under the heading "Additional Reports" in its "…" menu and its right-click menu, and choosing one opens that report. The row's main button and "Show in Finder" keep using the main protocol. Errors: a report deleted or renamed in Finder no longer appears the next time the menu opens. [paraphrase]
- **R3:** The main protocol stays the meeting's protocol everywhere else: "Open Protocol", "Open Last Protocol", the protocol path the automation API reports, and a pipeline retry, which rewrites only the main protocol. Errors: no error surface beyond R1. [inferred]
- **R4:** "Regenerate from File…" with an additional report chosen makes the protocol for the meeting the rule above names (its transcript, title and start time), not for the report as a meeting of its own, also when the meeting's own name or the template's name holds brackets. Errors: when no meeting's transcript can be found, today's "No transcript was found" message. [inferred]
- **R5:** "Move Meeting to Trash…" (gh-97), for one row or a selection, also moves the meeting's additional reports to the Trash, and its confirmation counts them. "Move Audio to Trash…" and the automatic deletion leave them, like the transcript and the protocol. Errors: a report the Trash refuses, a report that changed since it was found, and a folder that cannot be read leave the meeting as "Deletion incomplete" with gh-97's retry, which looks for reports again; after a crash the same record carries the reports already found. [inferred]

## Validation

Test first, from the criteria, in this order, at the cheapest layer that can fail:

1. **The naming rule (pure logic, with the existing target tests):** a plain report, a file with its own transcript, a bracket in the meeting's name, a bracket in the template's name, both meeting names present (the longer wins), no meeting present, a report name that is another meeting's protocol, and the built-in template's name.
2. **The write (with the existing regenerator tests, which inject every file operation):** an additional report lands at its own path with owner-only permissions and leaves the main protocol and other reports byte for byte; the same template replaces its report and trashes the old one; a meeting without a protocol gets its main protocol; a report that appears, changes or vanishes during the run, a failed write, a failed Trash move and a failed generation each leave every file as it was.
3. **The sheet (the existing sheet state and view tests):** the additional choice is preselected, each small line and the orange lines appear in their accepted wording, the meeting lines count the reports, no choice shows without a protocol, and Generate is disabled on a taken name.
4. **The row (the existing row action and window tests):** the "…" menu and the right-click menu both list the reports under their heading, in order, each opening its file; a row without reports has neither heading nor separator; a report removed from the folder is gone the next time the menu opens; "Open Protocol", "Open Last Protocol", the automation API's protocol path and a pipeline retry still use the main protocol only.
5. **The deletion (with gh-97's record and Trash tests, on a temporary folder):** reports enter the record in the same save as the pending deletion and before any move, a failed save moves nothing, a report whose identity changed is refused, a refused Trash move and an unreadable folder give "Deletion incomplete", an interrupted deletion comes back with its reports, a retry finds a report added since, a shared transcript blocks the reports, "Move Audio to Trash…" and the automatic deletion leave them.
6. **Both build variants:** the suite runs for the Homebrew and the App Store build, as CI does.
7. **Look:** a dev-only snapshot of the sheet in its three forms and of the row menu, to check that the longer lines wrap. How it looks stays the owner's check on the installed build.
